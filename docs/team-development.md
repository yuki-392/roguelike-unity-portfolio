# チーム開発

## 体制

5人で開発し、実装・レビュー・プロジェクト管理・アート制作を分担しています。

| 役割 | 主な責任 |
| --- | --- |
| 実装担当（自分） | Unity / C#によるゲーム機能の実装、テスト、プルリクエスト作成 |
| レビュー担当 | コードレビュー、フィードバック、マージ |
| プロジェクト管理 | タスク整理、進捗管理、メンバー間の調整 |
| ドット絵担当 | ドット絵の制作 |
| キャラクターイラスト担当 | キャラクターイラストの制作 |

## メンバーのバックグラウンド

レビュー担当とプロジェクト管理担当は、ゲーム開発のエンジニアではないものの、開発時点で業務としてソフトウェア開発に携わる現役エンジニアです。そのため、ゲーム固有の実装だけでなく、一般的なソフトウェア開発における可読性、変更範囲、進行管理の観点からも協力してもらっています。

キャラクターイラスト担当はゲーム開発の経験があり、ゲーム制作の流れやゲーム向けアセット制作の事情を理解したメンバーです。実装担当と制作担当で役割は異なりますが、ゲームとして一つの成果物にまとめるチーム構成になっています。

## 開発フロー

1. 担当する機能や修正内容を決める
2. 実装とテストを行う
3. 変更内容をプルリクエストとして提出する
4. 別メンバーがコードレビューを行う
5. 指摘内容を修正し、必要に応じて追加説明を行う
6. レビュー担当が確認してマージする

この流れにより、実装者だけの判断で変更を取り込まず、第三者が設計・可読性・影響範囲を確認してから統合しています。プルリクエストでは、変更の目的と確認方法を説明できるようにすることを意識しています。

## チーム開発で担当したこと

自分は主にUnity / C#によるゲーム機能の実装を担当しています。実装した変更はプルリクエストにまとめ、レビューで受けた指摘を反映してからマージしてもらっています。

コードだけでなく、ドット絵やキャラクターイラストなど別担当の成果物と組み合わせてゲーム画面を完成させるため、実装上必要なデータ形式や表示条件も確認しながら作業しています。

## AIを中心とした開発

設計、実装、テスト、UI QA、ドキュメント更新の実作業は、OpenAI Codexを中心に進めています。人間がコードを手作業で書き続けるのではなく、仕様や制約をCodexに伝え、Codexが設計案・コード・テストを生成し、その結果を確認して次の作業につなげるAI駆動開発の流れです。

人間が担当するのは、ゲームの方向性、要件、優先順位、受け入れ条件の決定と、AIが生成した成果物に対するレビュー・採否判断です。実装の主体はAIですが、何を作るか、どこまで採用するか、チームの基準を満たしているかは人間が判断しています。

Codexが生成・修正した設計やコードは、レビュー担当の現役エンジニアが、ゲーム開発に限らないソフトウェア開発の観点から確認しました。レビューで指摘された内容を修正し、確認後にマージすることで、AIによる実装をそのまま取り込まず、第三者による品質確認を経て統合しています。

インセプションはプロジェクト管理担当を中心に、5人全員で行いました。ゲームの目的、主要なプレイ体験、開発範囲、役割分担、優先順位をチームで整理してから、Codexを使った設計・実装・テストのサイクルへ進みました。

## 就職活動で見てほしい点

- 個人で完結させず、レビューを前提に変更を分割・説明していること
- 指摘を受けたコードを修正し、変更の意図を共有していること
- 実装、テスト、UI確認までを担当範囲として考えていること
- プロジェクト管理担当やアート担当と協力して、ゲームとして統合していること
