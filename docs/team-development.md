# チーム開発

## 体制

5人で開発し、実装・レビュー・プロジェクト管理・アート制作を分担しています。

| 役割 | 主な責任 |
| --- | --- |
| 実装担当（自分） | Unity / C#によるゲーム機能の実装、テスト、プルリクエスト作成 |
| レビュー担当 | コードレビュー、フィードバック、マージ |
| プロジェクト管理 | タスク整理、進捗管理、メンバー間の調整 |
| ドット絵担当 | ドット絵の制作 |
| キャラクターイラスト担当 | キャラクターイラストの制作 |

## 開発フロー

1. 担当する機能や修正内容を決める
2. 実装とテストを行う
3. 変更内容をプルリクエストとして提出する
4. 別メンバーがコードレビューを行う
5. 指摘内容を修正し、必要に応じて追加説明を行う
6. レビュー担当が確認してマージする

この流れにより、実装者だけの判断で変更を取り込まず、第三者が設計・可読性・影響範囲を確認してから統合しています。プルリクエストでは、変更の目的と確認方法を説明できるようにすることを意識しています。

## チーム開発で担当したこと

自分は主にUnity / C#によるゲーム機能の実装を担当しています。実装した変更はプルリクエストにまとめ、レビューで受けた指摘を反映してからマージしてもらっています。

コードだけでなく、ドット絵やキャラクターイラストなど別担当の成果物と組み合わせてゲーム画面を完成させるため、実装上必要なデータ形式や表示条件も確認しながら作業しています。

## 就職活動で見てほしい点

- 個人で完結させず、レビューを前提に変更を分割・説明していること
- 指摘を受けたコードを修正し、変更の意図を共有していること
- 実装、テスト、UI確認までを担当範囲として考えていること
- プロジェクト管理担当やアート担当と協力して、ゲームとして統合していること
