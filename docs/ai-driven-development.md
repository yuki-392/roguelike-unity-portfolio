# AI駆動開発

## 方針

このプロジェクトでは、OpenAI Codexを開発の実装主体として使用しています。設計、実装、テスト、UI QA、ドキュメント更新までをCodexとの対話で進め、人間がコードを一行ずつ手作業で書き進める従来型ではなく、AIが開発ループを回す方式を採用しました。

## インセプション

開発の起点となるインセプションは、プロジェクト管理担当を中心に5人全員で行いました。

- ゲームの目的と方向性
- プレイヤーに体験してほしい主要なプレイ体験
- 開発する範囲と優先順位
- 実装、レビュー、進行管理、アート制作の役割分担
- 実装後に確認する受け入れ条件

これらをチームで整理し、全員が同じ前提を持った状態でAI駆動の開発に移りました。

## 開発サイクル

```text
チームで要件・制約を決める
  ↓
Codexに設計案を作成させる
  ↓
Codexに実装とテストを行わせる
  ↓
テスト・UI QA・差分を確認する
  ↓
人間が採否を判断し、必要ならCodexに修正を依頼する
  ↓
プルリクエストを作成する
  ↓
別メンバーがコードレビューし、確認後にマージする
```

## 人間とAIの役割

| 担当 | 主な役割 |
| --- | --- |
| Codex | 設計案、コード、テスト、修正、ドキュメント更新の作成 |
| チーム | ゲームの目的、要件、制約、優先順位、受け入れ条件の決定 |
| 実装担当（自分） | Codexへの指示、生成物の確認、担当機能の調整、プルリクエスト作成 |
| レビュー担当 | 現役エンジニアとしてコード品質、設計、影響範囲を確認し、マージを判断 |
| プロジェクト管理担当 | インセプション、タスク整理、進行管理、チーム間の調整 |

AIに作業を任せるだけではなく、仕様を構造化して伝え、テスト結果や差分を確認し、必要な修正を次の指示に反映することを重視しました。これにより、AIを単なるコード補完ではなく、設計から検証までを含む開発工程の中心として扱っています。

Codexが生成・修正した設計やコードは、レビュー担当の現役エンジニアが、ゲーム開発に限らないソフトウェア開発の観点からレビューしました。指摘内容を修正し、確認を受けた変更だけをマージすることで、AIが実装主体でありながら、人間による第三者レビューを品質ゲートとして組み込んでいます。

## この開発方式で得た経験

- AIに渡す要件や制約を、実装可能な粒度まで整理する経験
- 生成されたコードをテスト、差分、画面確認から検証する経験
- AIが作成した変更を、プルリクエストとコードレビューの流れに乗せる経験
- チームで決めたゲームの方向性を、AIによる実装へ変換する経験
